# qB 做种兼容整理

媒体库保存真实文件；qB 下载路径保留指向媒体库的相对软链接。按指定分类（默认 meizang）筛选完整下载的影片及字幕/NFO，按任务名称归档并保留原文件名。归档后扫描媒体库，现有 Provider 提取元数据；本版未实现基于刮削标题的文件重命名。

在设置页填写 qB WebUI 地址、账号、密码、分类和媒体库目录。先测试连接，再保存并启用。默认关闭，启用后应用运行期间每分钟同步；手动同步使用已保存的配置。停止应用期间不执行清理。

源目录和媒体库必须在同一文件系统且可写。下载与媒体库必须分别在 fnOS 授权。采用临时硬链接落地目标（不复制数据且目标存在时失败），移除旧目录项后建立软链接。迁移前记录设备号、inode、大小和修改时间；中断可按台账恢复。创建软链接失败时尝试恢复下载路径。此过程是有日志的多步骤操作，不是整个事务原子完成。

正在做种的任务先暂停，轮询确认 stoppedUP/pausedUP 后操作，再恢复；原先停止的任务保持停止。设置中的 qB 实例、账号及目录映射在已有台账时锁定，避免切换实例误判任务移除。

Docker 路径映射要求媒体库和下载目录处于同一映射根内。例如 qB 挂载 `/vol1/media:/media`，将远端前缀设为 `/media`、本地前缀设为 `/vol1/media`，下载和媒体库均放在其子目录。相对链接在两边保持有效。qB 容器必须能读取媒体库。

清理只在两次成功读取完整任务列表、间隔至少 30 秒且任务均不存在后进行。网络或登录错误会重置确认；异常 JSON 不当作空列表。只处理台账中的 active 链接，并检查真实文件身份、授权和链接目标。目标改变或源路径被普通文件替代时保留并显示冲突。

在 qB 移除任务时请选择保留文件。媒藏不会调用删除任务/数据接口，无法控制 qB 或其他工具是否跟随软链接删除、修改目标。也请勿同时手动修改正在归档的路径。

此版经过本地文件系统故障测试及模拟 qB 响应测试。发布前仍需在实际 fnOS/qB 安装环境验证做种和权限。

API 依据：[qB 官方 WebUI 文档](https://github.com/qbittorrent/wiki/blob/master/WebUI-API-(qBittorrent-5.0).md)。
